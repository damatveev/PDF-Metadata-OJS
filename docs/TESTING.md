# Тестирование и приёмка

## Выполнено в среде разработки

- Синтаксическая проверка всех PHP-файлов через `php -l`.
- 47 автономных PHP-проверок: разбор ru/en, XMP, XXE, отсутствие текста, DOI библиографии, лимит превью, HMAC и привязка сеанса, срок действия, отпечатки, адаптер записи.
- Тесты адаптера используют **in-memory repository doubles**, а не установленный OJS. Они проверяют выбор полей, сохранение локалей, ORCID, добавление организаций, запрет чужих authorId/ролей и замены DOI.
- Node-тест контракта UI: регистрация компонента/hook, размещение в publication, передача ID, проверка permissions, сброс состояния, отсутствие innerHTML. Это не браузерный end-to-end тест.
- Проверка `version.xml` по DTD и одинакового набора ключей локализации en/ru/ru_RU.

Команды из каталога плагина:

```sh
find . -name '*.php' -print0 | xargs -0 -n1 php -l
php tests/adapter.php
node --check js/pdfMetadata.js
node tests/ui.cjs
```

`adapter.php` включает 32 теста из `run.php`, затем 15 проверок адаптера. Можно запускать `run.php` отдельно.

**Не выполнено здесь:** реальный Poppler/prlimit на Linux, установленный OJS с БД, авторизация реальных пользователей, откат БД, браузерная визуальная проверка, конкурирующие запросы. Ни один из этих сценариев не считается пройденным по результатам автономных тестов.

## Smoke-тест Poppler на сервере Linux

После установки и настройки плагина подготовьте обычный PDF с доступным для поиска текстом, заголовком статьи и разделом `Abstract` или `Аннотация`. Используйте искусственные данные.

```sh
php plugins/generic/pdfMetadata/tests/extract-smoke.php /absolute/path/to/ojs /absolute/path/to/test.pdf
```

Запускайте под пользователем PHP или с эквивалентными правами. Smoke-тест проверяет реальную цепочку Poppler и наличие предложений title/abstract, не выводя текст статьи. Отдельно проверьте PDF с XMP без текста, скан, зашифрованный, повреждённый PDF и документ длиннее 50 страниц.

## Обязательная матрица приёмки на staging

Создайте два журнала A/B, два материала, минимум две версии публикации, редактора с назначением и без назначения, автора, рецензента, менеджера. Сделайте снимок БД до тестов. Проверьте сценарии как через UI, так и непосредственными HTTP-запросами; скрытая кнопка не является контролем доступа.

| Сценарий | Ожидаемый результат |
|---|---|
| Включение плагина только в A | В B плагин не работает; API не предоставляет данные A |
| Раздел Publication в workflow A | Панель видима, существующие формы не нарушены, ошибок JS нет |
| Анонимный запрос, автор, рецензент, неназначенный редактор | Отказ, без содержимого PDF/метаданных |
| Подмена submissionId, publicationId, fileId на принадлежащие B | Отказ до извлечения или записи |
| PDF рецензии/внутреннего вложения того же submission | Отказ; доступны только исходные файлы |
| POST без CSRF / с неправильным CSRF | 403 |
| Authorization header при cookie-сессии | Отказ, CSRF нельзя обойти заголовком |
| Опубликованная, scheduled или не последняя publication | Отказ; БД неизменна |
| Нажать только «Извлечь» | БД метаданных неизменна, все checkbox выключены |
| Выбрать только title на ru | Изменяется только title.ru, остальные локали/поля сохранены |
| Title/abstract с HTML, скриптом, кавычками | В интерфейсе нет выполнения кода, при записи безопасный текст |
| Список литературы | После перечитывания совпадает citationsRaw; штатный список цитат обновлён |
| Автор с ORCID и несколькими локалями | Изменяются только выбранные имя/email, ORCID/локали сохранены |
| Новая организация автору с существующим ROR | Добавлена новая, старый ROR и организации сохранены |
| Новый автор без email / чужая userGroupId | Валидация отклоняет, ни одно выбранное поле не сохранено |
| Журнал требует дополнительные поля автора, например competing interests | Валидация отклоняет отсутствие; создайте автора штатной формой и сопоставьте его |
| Ошибка affiliation validator после создания автора | Транзакция откатывает и автора, и остальные изменения |
| Попытка очистить поле пустой строкой | Отклонена; используйте штатную форму для удаления данных |
| Новый DOI, отключённые DOI публикаций, дублирующий DOI, существующий DOI | Запись только нового уникального DOI при включённом типе; остальные случаи отклонены |
| Сменить выбранный PDF/версию публикации во время запроса | Старый результат не применяется к новой версии; запрос прерывается |
| Изменить title/автора/организацию/references через другую форму после просмотра | Apply возвращает 409, требует нового извлечения |
| Изменить PDF после просмотра | 409 |
| Подмена ticket, другой пользователь/сессия, ожидание >15 минут | Отказ |
| Два Apply по одному ticket с добавлением автора | Один успешный, второй конфликт; нет двойного автора |
| Два извлечения одновременно | Один обрабатывается, второй 429 |
| Более 20 МиБ, вывод более 2 МиБ, превышение времени/CPU | Отказ с ограничением; дочерние процессы завершены |
| Скан | noText, возможны только встроенные метаданные, инструкция OCR |
| PDF >50 страниц | Предупреждение partial; нельзя считать references полными |
| Удаление/отзыв доступа к файлу или прав пользователя перед Apply | Отказ при повторной проверке |
| Завершение/ошибка извлечения | Временный input.pdf и его каталог удалены |
| ru/en интерфейс, узкое окно, клавиатура | Читаемые поля, видимый focus, корректные подписи и порядок Tab |

Проверьте PostgreSQL либо MySQL/MariaDB на той СУБД, которая используется в журнале. Отдельно воспроизведите конкуренцию со штатной формой авторов и сторонними плагинами: они могут не соблюдать блокировки этого плагина. До подтверждения поведения не допускайте параллельное редактирование одного материала.

## Диагностика

`unavailable`: Linux/пути Poppler/prlimit/proc_open. `configuration`: временный каталог и secret. `invalidPdf`: повреждение/шифрование/ошибка Poppler. `limit`: размер/время/вывод. `validation`: структура details с ошибками OJS. `conflict`: перечитать публикацию и извлечь повторно.

Лог `pdfMetadata failure <class>` сознательно не содержит содержимого PDF, путей или stderr. Для диагностики парсера воспроизводите ошибку изолированно на синтетическом PDF, не включайте запись документов и персональных данных в общий журнал.
