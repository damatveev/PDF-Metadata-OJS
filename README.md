# PDF Metadata — плагин для OJS 3.5.x

Версия плагина: **1.0.0.0**. Лицензия: GPL-3.0-or-later.

Плагин извлекает предложения из PDF, уже загруженного в исходные файлы submission, и добавляет панель **«Метаданные из PDF»** в раздел **«Публикация»** редакционного workflow. Редактор видит текущие и предлагаемые значения, исправляет их и явно выбирает изменения. Извлечение само по себе ничего не записывает в публикацию.

**Статус:** исходники и автоматические автономные тесты подготовлены; интеграционный запуск на установленном OJS с БД и Poppler ещё требуется. Совместимость проверялась чтением конкретных исходников OJS/PKP/UI, а не запуском полного сайта. Перед использованием на рабочем журнале выполните [приёмочные проверки](docs/TESTING.md).

## Возможности и границы

| Поле | Извлечение | Сохранение |
|---|---|---|
| title | XMP → PDF Info → первая подходящая строка | Только выбранная локаль публикации |
| abstract | XMP description → раздел Abstract / Аннотация / Резюме | Простой текст с безопасными переносами строк |
| keywords | Заголовок ключевых слов → XMP subject / PDF Keywords | Массив, один термин на строку, выбранная локаль |
| authors | XMP creators / PDF Author | Явное сопоставление с authorId либо добавление; имя, фамилия и email подтверждаются вручную |
| affiliations | Строки организаций в начале статьи | Добавление организаций конкретному автору; существующие записи и ROR сохраняются |
| DOI | Идентификатор XMP или начало статьи до библиографии | Назначение только при отсутствии DOI и включённых DOI публикаций; существующий DOI меняется в штатном OJS |
| references | Раздел References / Bibliography / Литература / Список литературы | Замена citationsRaw целиком; штатный DAO OJS обновляет цитаты |

Имена не разделяются автоматически: порядок имени и фамилии зависит от языка. Адреса email не выдумываются. Если PDF не содержит структурированных авторов, используйте извлечённый текст и кнопку добавления строки сопоставления. Привязка организации к человеку всегда ручная. Аффилиации добавляются, а не заменяются; удаление и исправление существующих организаций выполняется в штатной форме автора.

Обрабатываются только исходные файлы `SUBMISSION_FILE_SUBMISSION`. Рецензии, внутренние вложения, корректуры и файлы других стадий не доступны через плагин. Сначала загрузите нужную версию PDF через файловый менеджер OJS. Отдельного незащищённого загрузчика в плагине нет.

Доступ: менеджер журнала или назначенный редактор раздела, с правом редактирования метаданных OJS. Только последняя версия публикации со статусом `STATUS_QUEUED`. Авторы, рецензенты, помощники редактора, опубликованные и запланированные версии в эту реализацию не включены. Плагин включается отдельно для каждого журнала, без ID или URL конкретного журнала в коде.

## Требования

- OJS 3.5.x с его штатными зависимостями Composer; PHP 8.2+ и необходимые OJS расширения, включая `mbstring`, DOM/XML.
- **Linux для сервиса извлечения**, Poppler (`pdfinfo`, `pdftotext`), `prlimit` из util-linux, доступный `proc_open`.
- Закрытый локальный временный каталог вне web root, доступный пользователю PHP; отдельный случайный секрет плагина.
- БД с поддержкой транзакций; для MySQL/MariaDB таблицы должны использовать InnoDB.
- Сборка JavaScript не нужна: плагин использует Vue из OJS через `pkp.modules.vue`. Собственный vendor или второй экземпляр Vue не устанавливается.

На Windows PHP можно запустить автономные тесты, но обработчик PDF намеренно возвращает `unavailable`: неограниченный запуск без Linux resource limits не предусмотрен.

## Установка

1. На тестовой копии OJS сделайте резервную копию БД и файлов. Проверьте версию OJS и используемый commit; для Git-установки — также `git submodule status lib/pkp lib/ui-library`.
2. Распакуйте архив так, чтобы существовал каталог `plugins/generic/pdfMetadata/` и непосредственно внутри него `version.xml`, `PdfMetadataPlugin.php`, `index.php`. Регистр букв важен на Linux. Можно загрузить `.tar.gz` через штатную установку плагинов OJS, если она разрешена администратором.
3. На Debian/Ubuntu установите необходимые серверные пакеты:

   ```sh
   sudo apt-get install poppler-utils util-linux
   sudo install -d -m 0700 -o www-data -g www-data /var/lib/ojs-pdf-metadata
   php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
   ```

   Замените `www-data` пользователем вашего PHP-FPM. Последняя команда генерирует секрет: сохраните его в конфигурации, не в репозитории.

4. Добавьте в `config.inc.php` OJS (значение `secret` замените результатом генерации):

   ```ini
   [pdf_metadata]
   temp_dir = /var/lib/ojs-pdf-metadata
   secret = "REPLACE_WITH_64_RANDOM_HEX_CHARACTERS"
   pdfinfo = /usr/bin/pdfinfo
   pdftotext = /usr/bin/pdftotext
   prlimit = /usr/bin/prlimit
   ```

   Доступ к конфигурации должен быть закрыт для посторонних. После ротации секрета все старые сеансы просмотра становятся недействительными. Пример строки не является рабочим секретом.

5. В настройках журнала откройте «Веб-сайт → Плагины → Установленные плагины → Общие плагины» и включите «Метаданные из PDF». При изменениях файлов очистите кэши OJS штатными средствами и обновите страницу браузера.
6. Откройте материал под редакционной учётной записью → «Публикация» → «Метаданные из PDF» → «Открыть помощник». Выберите исходный PDF и язык целевых полей.
7. Извлеките предложения, проверьте их, отметьте только нужные поля. Для авторов выберите существующую запись либо создание новой. Заполните обязательную почту и выберите роль из групп этого журнала.
8. Нажмите «Сохранить выбранные изменения». Закройте и снова откройте workflow для обновления остальных форм. Перед импортом завершите редактирование в других открытых формах этого материала.

Собственных таблиц, миграций, cron-заданий и внешних API у плагина нет. Для удаления отключите его и удалите только каталог плагина. Уже сохранённые метаданные остаются в OJS.

## Fallback и пределы

`pdfinfo` проверяет читаемость PDF и шифрование; затем берутся XMP и PDF Info, после чего `pdftotext` извлекает текст. Невалидный или зашифрованный файл отклоняется. Если XMP отсутствует/повреждён, остаются Info и эвристики текста. Если текст не извлекается, доступны только встроенные метаданные и предупреждение.

Для скана выполните OCR на своём сервере/компьютере, проверьте результат и загрузите PDF с текстовым слоем. Автоматического OCR и GROBID в этой версии нет. PDF никогда не уходит в Crossref, GROBID, LLM или другой внешний сервис. Научные статьи с колонками, сложной вёрсткой и нестандартными заголовками могут потребовать ручной правки.

Пределы: PDF 20 МиБ; первые 50 страниц; максимум 2 МиБ вывода каждого дочернего процесса; 15 секунд wall time и 10 секунд CPU на процесс; 512 МиБ адресного пространства процесса; 64 дескриптора. До трёх последовательных процессов, максимум около 45 секунд. На один временный каталог допускается один запуск извлечения; параллельный получает HTTP 429. На веб-сервере задайте ограничение тела запроса 256 КиБ для `pdf-metadata` и rate limit по учётной записи/сессии, не ограничивая штатный upload OJS этим размером.

Превью текста ограничено 30 000 символов. Уверенность — качественная эвристическая отметка, не статистическая вероятность. Поля не выбираются автоматически даже при наличии XMP.

## Файлы

```text
pdfMetadata/
├── index.php
├── version.xml
├── PdfMetadataPlugin.php          # hooks и подключение UI
├── classes/
│   ├── MetadataController.php     # routes, политики, транзакция
│   ├── MetadataService.php        # адаптер репозиториев OJS
│   ├── SubmissionPdf.php          # доступ к исходному PDF через storage OJS
│   ├── PdfExtractor.php           # ограниченный запуск Poppler
│   ├── MetadataParser.php         # XMP, Info, эвристики
│   ├── Ticket.php                 # подписанный сеанс просмотра
│   └── Failure.php
├── js/pdfMetadata.js              # Vue UI, без отдельной сборки
├── styles/pdfMetadata.css
├── locale/{en,ru,ru_RU}/locale.po
├── tests/{run.php,adapter.php,ui.cjs,extract-smoke.php}
├── docs/{ARCHITECTURE.md,TESTING.md,COMPATIBILITY.md}
├── README.md
└── LICENSE
```

В OJS 3.5 основной русский код локали — `ru`; добавлен также запрошенный `ru_RU`. Локали метаданных не подменяются: сервер использует список языков конкретного материала/журнала.

Подробности: [архитектура и API](docs/ARCHITECTURE.md), [тестирование](docs/TESTING.md), [проверенная база совместимости](docs/COMPATIBILITY.md).
